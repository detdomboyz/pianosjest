# Локальные части пианистического курса, v1

Статус 7 ноября 2026: **формат и локальная подготовка одной темы реализованы и проверены**. Экспортёр работает на опубликованных встроенных данных; загрузчик частей, объединение с пользовательским слоем и браузерное переключение на новый формат — следующие отдельные этапы. Рабочий сайт продолжает использовать прежние проверенные файлы сборки.

## Воспроизведение

```powershell
npm run build:lesson-parts
node --preserve-symlinks --preserve-symlinks-main --test tests/piano-lesson-parts.test.cjs
```

`tools/build-lesson-parts.cjs` проверяет текущий опубликованный SHA `dist/web/web-release.json`, все браузерные файлы и соответствие локальных музыкальных адаптеров. Через существующий VM-помощник читает встроенную тему `builtin-theme-1aeq2x1` (course01-01…08). Это data initialization без boot, доступа к браузерному хранилищу, MIDI, звуку или локальному trainer-content.json. Папка результата — `dist/lesson-parts/<release>`; `dist/web` не меняется.

API — `piano-lesson-parts.js`, декларации — `piano-lesson-parts.d.ts`. Модуль Node не включён в публичный allowlist. Строгие типы проверяются существующим TypeScript 5.8.3 без emit и установки пакетов, в том числе отрицательные примеры `piano-lesson-parts.typecheck.ts`.

## Два отдельных документа

Манифест имеет `schema: melodiajest-piano-parts`, `version: 1`, `instrument: piano`, `catalogFormat: 7`, `source`, `themeOrder`, `lessonOrder`, `parts`. `source` содержит выпуск встроенного каталога и SHA исходного web-манифеста. Версия контейнера данных не является оценочной подписью урока.

Каждый descriptor содержит themeId, относительный key, SHA256, число **байт UTF-8** и упорядоченные lessonIds. Список themeOrder соответствует descriptors, lessonOrder хранит исходный плоский порядок даже при перемежающихся темах. Дубли ID и несовпадающие множества отвергаются.

Часть имеет `schema: melodiajest-piano-topic`, `version: 1`, `instrument: piano`, `catalogFormat: 7`, тот же `source`, полные `theme` и `lessons`. Один пакет содержит одну учебную тему. У темы допустим исходный contentKind=null/отсутствует или exercise; у каждой записи обязательно exercise. Piece, другой инструмент, тема, выпуск или неподдерживаемый формат отвергаются. Имя и положительный целый порядок темы, порядок записей проверяются; их исходные значения сохраняются.

Уроки сохраняются в существующей сериализации каталога v7: ID, themeId, порядок, pattern, rhythm, fingeringSpec, guide, learning, contentReview/предыдущие редакции и остальные поля. Проекция через действующий PianoCatalogAdapter подтверждает обратимость; полные учебные объяснения не обрезаются ради пакета. `savedAt` верхнего уровня каталога не переносится: это время экспорта, а не музыкальные данные. Прочие неизвестные корневые поля каталога отвергаются, личный прогресс не включается.

Сериализованный rhythm v7 не содержит вычисляемый stepIndex. Поэтому его подпись нельзя подменять runtime-подписью зачёта. Проверка полного обратного прохода через настоящий `applyCatalogSnapshot` сравнивает 572 runtime-подписи и ноты/время/пальцы; классификация сравнивается с явным нормализованным contentKind исходного снимка.

## Хеши, границы и запись

JSON — UTF-8. SHA относится к **конкретным байтам**, включая завершающий перевод строки. Одинаковый сериализованный вход даёт одинаковые байты; формат не объявляется универсальным canonical JSON для произвольной перестановки полей.

- Часть: `parts/v1/<sha256>.json`, не более 1 МиБ.
- Манифест: `manifests/v1/<sha256>.json`, не более 256 КиБ.
- За одну сборку: 1–64 темы; массивы ID ограничены, пустые и повторные ID запрещены.
- SHA ожидаемого манифеста поступает из доверенного источника выпуска; затем проверяются размер/SHA каждой объявленной части, UTF-8, JSON, версия и идентичность. Сам по себе хеш не является цифровой подписью автора.

Перед хешированием/разбором создаётся ограниченная копия входных байтов, чтобы проверка и парсер работали с одним содержимым. Необъявленные части, лишние/недостающие файлы, несогласованный источник и повреждённые данные приводят к отказу. Ноты не исправляются автоматически ради прохождения проверки.

`write` разрешает собственные `dist/lesson-parts` и `tmp`. Каждый родительский компонент проверяется до создания следующего; ссылки/junction не допускаются. Файлы создаются с `wx`; существующие регулярные файлы принимаются только при полном совпадении размера/байтов. Манифест записывается после частей, записанные байты перечитываются. Коллизия или частичная запись сохраняется как ошибка, существующий файл не затирается. Нет обхода каталога старых хешей, удаления или сетевых запросов.

## Граница следующего браузерного этапа

Реализовано: чистые build/read/assemble/write, декларации, локальная неизменяемая тема и воспроизводимый манифест. Не подключены: браузерный fetch/cache, удалённые URL, S3/CDN, отдельный пользовательский слой и перенос существующего хранилища.

До подключения нужны контракт UI и проверенный контроллер: действующий bundled-каталог остаётся доступным; при недоступной сети, повреждении или несовпадении версии старая рабочая версия сохраняется, ошибка видна, есть повтор. Частично проверенный набор не применяется. Личные ноты, классификация, порядок, редакции и прогресс не заменяются обновлённым встроенным материалом; конфликт требует отдельного решения. Смена источника не запускает MIDI/звук.

После этого потребуется изолированное сравнение на **одном исходном выпуске**: реальная загрузка/отображение, кеш, отказ сети и сохранность личной редакции/памяти. Нынешний экспортёр всё ещё инициализирует полный каталог, поэтому малый размер одной темы не доказывает ускорение сайта или пользу S3. Доставка учебных данных и закрытые зашифрованные резервные копии остаются разными задачами.

Первичные источники: [RFC 8259 §§4, 8.1, 9](https://www.rfc-editor.org/rfc/rfc8259.html) — данные JSON/UTF-8 и границы парсера; [Node createHash](https://nodejs.org/docs/latest-v20.x/api/crypto.html#cryptocreatehashalgorithm-options) — SHA256; [Node fs flags](https://nodejs.org/docs/latest-v20.x/api/fs.html#file-system-flags) — `wx`. Открытая документация Node 20.20.2 новее установленной 20.15.1; использованные API фактически проверены на текущем Node.

Локальный [план применения v1](LESSON_PACKAGE_UPDATE_CONTRACT.md) реализован отдельно: проверка старого/нового pin, запрет downgrade, сохранение расположения, отказ при частной редакции и повторная сверка каталога. Он только готовит отдельный результат в памяти. Это не подключённый браузерный загрузчик и не атомарная запись storage.

В фазе 23 отдельно реализован [браузерный транспорт](LESSON_PACKAGE_LOADER_CONTRACT.md), использующий общий data-only codec с Node-производителем. Он проверяет fetch/cache/WebCrypto и выдаёт замороженный пакет в памяти. Связка с личным слоем, store и всеми рабочими writers ещё не подключена.
