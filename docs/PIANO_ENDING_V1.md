# Конечная пауза: исполнительский контракт v1

Первое применение — `detail-p-rhythm-final-rest-01`, выпуск **23.5.22**. Это опциональная граница короткой фразы, не модель педали или удержанных голосов.

```js
learning.ending = { version: 1, endBeat: 4 };
// C4/1: startBeat 0, durationBeats 1;
// C4/1: startBeat 2, durationBeats 1;
// Последний NoteOff у доли 3, конец наблюдения у доли 4.
```

`endBeat` использует ту же шкалу четвертных единиц, что `rhythm.steps.startBeat`. Требуются конечные положительные длительности, упорядоченные начала и конец строго после всех нот. v1 ограничен **64 четвертными единицами от первой ноты**, чтобы повреждённый импорт не создал переполняющийся браузерный таймер. Неизвестная версия, `null`, строковый конец и неверные границы отклоняются; исходные поля личной редакции не исправляются молча.

Чистая функция `PracticeAssessment.pianoEnding` вычисляет границу относительно первой ожидаемой атаки и BPM текущей попытки. `assessPiano` получает `ending`, `observedUntil` и `observationInterrupted`. Отпускание последнего звука не доказывает последующую тишину: для чистого результата нужно наблюдение до границы, без новой атаки внутри последней паузы и без замеченного разрыва входа. Отсутствующее отпускание и удержание через паузу дают отказ. У отпускания есть проектный допуск **min(130 мс, 12% доли)**; он не сдвигает конец и не разрешает новую атаку внутри паузы. Проверки длительности/вступлений применяются дополнительно.

В приложении таймер конца создаётся после последней ожидаемой атаки. Он использует сохранённый BPM попытки; движение ползунка не сокращает её задним числом. Сброс, выбор другого урока и смена режима отменяют ожидание. Поздний callback проверяет текущую границу повторно. Если после границы приходит новая атака, сначала завершается прежняя попытка; новая атака уже вне её окна. Прямой ранний вызов завершения не обходит ожидание.

Для нового контракта запоминается источник событий. Замеченные отключение, замена/закрытие выбранного Web MIDI-входа, смена входа, потеря статуса моста и ошибка EventSource делают наблюдение прерванным. Доступное состояние входа повторно читается при завершении. Возврат устройства не восстанавливает пропущенный участок; нужен новый заход. Ошибка неиспользуемого моста не обесценивает прямой MIDI-вход. Подключение устройств по-прежнему требует действия пользователя; веб-сборка к локальному мосту не обращается.

Это проверка записанных MIDI-событий и доступных сигналов соединения. [Web MIDI API, §5.6](https://www.w3.org/TR/webmidi/#midiconnectionevent-interface) предупреждает о возможной задержке системных уведомлений. Мгновенное обнаружение любого аппаратного разрыва, акустическое затухание, пальцы и педаль не доказаны. Урок выполняется **без педали**. Настоящее устройство в этой партии не проверялось.

Без `learning.ending` старые сигнатуры, поля результата и завершение по последнему отпусканию сохраняются. Глобальный `PracticeAssessment.VERSION` остаётся **1**. Для нового контракта ending включён в `pianoSignature`, результат содержит `endingVersion`, `endingObserved`, `endingInterrupted`, `restErrors`; смена границы не наследует прежний зачёт. Архив прежней редакции прогресса сохраняется штатным `record`.

Демонстрация расширяет длительность последнего шага до конца паузы, но не удлиняет ноту. В этом уроке осциллятор отключается у границы её длительности, клавиши освобождаются и проигрыватель продолжает тишину. Дополнительный таймер визуального отпускания отменяется при паузе, остановке, перемотке и сбросе. В памяти разбор и указание конечной паузы отсутствуют в интерфейсном DOM; feedback остаётся нейтральным до оценки.

Каталог остаётся v7. Поле ending хранится в `learning`, сохраняется при JSON-переносе и в compatibility-архиве общего документа. Нотный граф для чтения пока не становится общей редакторской моделью пауз. Подробные тесты — `tests/piano-terminal-rest.test.cjs`; партийные доказательства — [отчёт 17](reports/piano-curriculum-2026-11-06-17.md).
