## Минимальный проверяемый путь

1. Проверить актуальную локальную версию,manifest/SHA публичных файлов и незавершённый checkpoint. Для234 переиспользованы точные41файл/709runtime;здоровые тяжёлые проверки ради подключения не повторять.
2. Запустить только собственный loopback preview с физическим временным dataDir на D:,отдельным гостевым origin и ownership receipt PID/creationTime/ports. Не читать trainer-content.json или пользовательский прогресс. Учесть паруMiB fixture и минимум2GiB свободного запаса;один тяжёлый процесс.
3. По свежему browser.tabs.list() сверить ID/providerTabId/URL старой собственной вкладки. Если её нет,отметить отсутствие;несовпавшие вкладки не закрывать. Для новой проверки создать свою временную вкладку.
4. Через объявленную capability viewport задать390×844. Использовать AX для текущих элементов;при повторяемой developer-QA допустимы DOM-read-only и Playwright locators по реально наблюдённым ID. Не выполнять мутации DOM через evaluate.
5. Обычной навигацией/прокруткой привести заголовок и карточку в viewport. Сохранить координаты,ширины,112px/22.4px при пяти строках,проверить видимый нативныйJPEG. Положительные inside-list без фактической видимости не считать успехом. Не объявлять автопозицию всей страницы исправленной обычным scroll.
6. Проверить нужные раскрытие/клавиатуру/фокус/сохранение вида/подготовки/ноты по изменению;переиспользовать уже успешные доказательства на точном коде. Считать практику виртуальной отдельно от аппаратного MIDI. Прочитать warn/error консоли.
7. Вызвать viewport.reset(),закрыть свою вкладку и проверить инвентарь. Штатно остановить свой preview,дождаться exit и проверить закрытие своих портов. Не объявлять exit старого исчезнувшего процесса известным.
