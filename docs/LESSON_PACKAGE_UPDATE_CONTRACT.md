# План применения пакета уроков, v1

7 ноября 2026. Локальная реализация `piano-lesson-package-update.js` и строгие декларации `.d.ts` готовят безопасное применение [частей каталога](LESSON_PARTS_CONTRACT.md). Модуль Node не включён в публичный allowlist и не подключён к браузеру. Он не читает/пишет storage, файлы пользователя, MIDI, звук или сеть.

## Что уже делает код

`prepare({active, previous, incoming, catalog})` получает старый и новый пакет: доверенный pin, байты манифеста и Map объявленных частей. Pin содержит release, SHA web-источника и SHA манифеста. Оба пакета полностью проверяются действующими `readManifest/assemble`; активный pin должен точно совпасть со старым. Хеш проверяет целостность, а доверенность pin обязан обеспечить будущий контроллер выпуска.

Версии — три числовых компонента 0…999999 без ведущих нулей. Сравнение числовое: 23.5.9 ниже 23.5.40. Более ранняя версия запрещена. У того же выпуска допустим только тот же pin; другой источник/манифест с тем же номером отвергается. В v1 поддержан прежний набор ID тем/уроков; добавление/удаление встроенных записей требует отдельного контракта. Личные дополнительные записи остаются в каталоге.

Код сравнивает каждую целевую запись с прежней встроенной и входящей. Неизменённая встроенная запись может получить новую редакцию; уже совпавшая со входящей сохраняется. Личное изменение нот, ритма, пальцев, описания, guide, learning, происхождения, классификации или неизвестного поля создаёт конфликт. Удалённая пользователем запись/тема не воссоздаётся автоматически. Изменённое название/классификация темы тоже даёт конфликт.

Порядок массивов тем/записей, текущие order и размещение themeId сохраняются как отдельные настройки расположения. Поэтому ручная сортировка или перенос урока в личную тему не мешают обновлению его неизменённого содержания. Исходный каталог, входящие байты и старый пакет не меняются.

Если есть хотя бы один конфликт, весь пакет получает status=blocked: промежуточный кандидат не выдаётся и `materialize` отказывает. В сводке остаются только типы конфликтов и ID, без текста личных заметок. Ручное разрешение конфликта и архивы ожидающего импорта здесь не реализованы.

## Повторная проверка перед получением результата

`materialize(plan, latestCatalog)` принимает только настоящий живой план этого экземпляра модуля. Сводка глубоко заморожена; сериализованный/поддельный план не подходит. SHA актуального локального каталога должен совпасть со снимком подготовки, иначе требуется новый `prepare`. Порядок и любые изменения даже вне обновляемой темы учитываются. Только savedAt исключён из сравнения: это время экспорта, при выдаче результата сохраняется его последнее значение.

Возвращаются новый v7 catalog и новый active pin. Каждый вызов выдаёт отдельную копию. Это подготовленный результат в памяти, **не запись и не атомарный commit браузерного хранилища**. После reload план строится заново. Для будущего применения нужны общий для реальных вкладок lock/транзакция, повторное чтение под ним, сохранение до переключения видимого каталога и обработка ошибки записи. Эти гарантии не заменяются наличием WeakMap или сравнением SHA.

Прогресс и настройки остаются отдельными хранилищами. Модуль не переносит зачёт на изменённую музыку и не удаляет старую историю. Проверка через настоящий импортёр сопоставляет runtime-подписи, а отдельный тест изменённой длительности проверяет новый ключ оценки и сохранение прежней памяти в history действующего assessor. Известная фраза по-прежнему не становится неизвестным слуховым тестом.

## Ограничения входа и проверки

Вход — сериализуемые данные v7: themes/lessons и необязательный savedAt. Неизвестное корневое поле, например progress, отвергается. Проверяются ID, ссылки на темы, положительный целый order, дубли; содержимое личных полей не исполняется. Нефинитные числа, функции, циклы, accessors, нестандартные объекты и разреженные массивы отвергаются; undefined-поля объектов отсутствуют, как в JSON v7.

Границы: 32 МиБ JSON, строка до 1 МиБ, глубина 80, до миллиона узлов, 2048 тем / 10000 записей. Бюджет расходуется во время копирования, а не только после создания полного результата. Модуль не обрезает материалы ради лимита. Сбой валидации/целостности возвращается ошибкой, исходный каталог остаётся у вызывающей стороны.

```powershell
node --preserve-symlinks --preserve-symlinks-main --test tests/piano-lesson-package-update.test.cjs
```

Типы проверяются существующим официальным TypeScript 5.8.3 с strict/noEmit; примеры `.typecheck.ts` включают запрет передачи progress, поддельного плана и изменения сводки. Установка пакетов не нужна.

Сайт продолжает использовать прежний bundled-каталог 23.5.40. Не реализованы браузерный decoder/fetch/cache, запись с координацией вкладок, UI ошибок/повтора/конфликтов, S3/CDN и миграция пользовательского хранилища. До подключения нужны отдельная реализация и изолированная браузерная проверка сетевого/дискового отказа с сохранением работающей версии. Уменьшение числа байт темы не является доказательством ускорения сайта.

Первичные источники: [RFC 8259 §§4, 8.1, 9](https://www.rfc-editor.org/rfc/rfc8259.html) — JSON и допустимые границы; [ECMAScript JSON.parse](https://tc39.es/ecma262/#sec-json.parse) — разбор данных; [Node createHash](https://nodejs.org/docs/latest-v20.x/api/crypto.html#cryptocreatehashalgorithm-options) — SHA. Числовая схема версий, политика конфликтов и границы — решения проекта, а не требования источников.
