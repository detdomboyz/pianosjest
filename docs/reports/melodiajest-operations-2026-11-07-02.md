# MelodiaJest: транзакционное обновление и откат

7 ноября 2026 года, эксплуатационная партия 02. Публичный сайт остаётся **23.5.33**. Тестовый кандидат 23.5.34 использовался только в изоляции и **не опубликован**. Уроки и их педагогические статусы не изменены.

## Реализовано

`deploy/shared-host/release_update.py` использует проверенный архиватор партии 01. Серверный CLI ограничен `/opt/melodiajest` и сервисом `melodiajest-static`; доступны `plan`, `install`, `rollback`, `recover`. Локальный запуск приложения остаётся прежним, сторонние Python/npm-пакеты не добавлены.

Перед изменением проверяются ожидаемый SHA текущего манифеста, состав архива, неизменность трёх конфигов, отдельный снимок исходников для изменённого выпуска, повышение версии, место и инфраструктура. Содержимое ставится в отдельный каталог; существующий релиз с отличающимися данными не перезаписывается. Сохраняются исходный архив и проверенная восстановлением копия прежних файлов/конфигов. Источники, конфиги и приватные данные не копируются в публичный каталог.

Общая блокировка совпадает с реальным `deployment_guard` Libreta (`/run/lock/libre-deploy.lock`), собственная — `ops/operation.lock`. При занятости выполнение прекращается без принудительного снятия/удаления lock. Указатели `current`/`previous` переключаются через замену ссылки; файлы/журнал синхронизируются на диск. Журнал хранит подготовку, переключение, проверку, подтверждённый итог или неуспешное восстановление. Незавершённая операция блокирует новое обновление до явного `recover`.

Ошибка запуска или проверки возвращает прежнюю ссылку, пересоздаёт только свой контейнер, проверяет его и восстанавливает прежний `previous`. Повтор того же артефакта не пересоздаёт контейнер и не делает ещё одну копию. Изменения образа, Compose/Caddy-конфигурации, очистка и чужие сервисы этим инструментом не выполняются.

Production-проверка предусматривает SHA всех публичных файлов, главную страницу, приватные маршруты, HTTP/HTTPS-www редиректы с путём/запросом, запрет POST, здоровье/образ/изоляцию контейнера, неизменность Caddy и доступность соседей. Публикация нового содержимого через этот backend ещё должна пройти отдельную реальную проверку; локальный тест команды Compose не выдаётся за уже выполненную выкладку.

## Доказательства

- `npm test`: **638/638**, без ошибок.
- На Windows выполнены 7 проверок конфигурации/команды; 18 POSIX-сценариев там пропущены явно. На сервере **все 25 проверок прошли**, пропусков нет: ссылки, flock/fsync, сбой запуска/проверки, незавершённый журнал, восстановление повреждённого тестового кандидата, отказ отката, конфликт SHA/версии/конфигов, повторный запуск и неизменяемый каталог.
- Реальный отдельный Nginx, сеть `none`, без публичных портов и production-томов: успешное обновление → повтор без пересоздания → явный откат → новое переключение с намеренной ошибкой после HTTP-проверки → автоматический откат. На каждом из пяти проходов сверены 28 файлов.
- `plan` на фактическом сервисе/VPS и архиве партии 01 подтвердил неизменный выпуск и допустимую инфраструктуру. Все три локальных конфига совпадают с подтверждёнными серверными хешами.
- ID работающего контейнера, production `current` и общий Caddy сохранены. MelodiaJest, Libreta, Praicer, Grigorova после проверки — HTTP 200. Тестовые контейнеры удалены.
- Новый снимок содержит **325 выбранных файлов исходников/тестов/документов**, 1 642 940 байт, SHA256 `911532b52a1563babb87bdd6d1fca283129a601aa525d4d87155708befa84de4`. Он не заменяет личный браузерный экспорт.

## Эксплуатационный checkpoint

Первое постоянное размещение проверенного CLI и восстановление нового серверного снимка были остановлены **общей занятой блокировкой**, до изменения рабочих файлов. Она не снималась; чужая операция не прерывалась. Подготовленные программы и архив сохранены в закрытой папке `ops/update-check-20261107-02`, локальные доказательства — в JSON этого отчёта. Финальный статус размещения читается из поля `tooling` машинного отчёта и состояния продукта; ожидание не считается выполненной установкой.

Следующий шаг после свободного lock — завершить идемпотентное размещение в `ops/tooling/updater-<hash>` и восстановление нового снимка. Затем вернуться к сохранённой музыкальной подготовке `course03-08`; первый содержательно изменённый выпуск проверить через установленный CLI. S3/шифрование, ежедневные таймеры и ротация остаются отдельными этапами. Домен, Git commit/push и `guitarjest` не менялись.
