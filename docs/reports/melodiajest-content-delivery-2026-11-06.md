# Уроки в S3: оценка предложения пользователя

6 ноября 2026 года, версия 23.5.30. Пользователь предложил хранить уроки в бакетах для оптимизации сборки. Проведена оценка; S3-загрузка, изменение бакетов/политик/DNS и перенос материалов не выполнялись. Это кандидат архитектуры, не включённый новый runtime и не учебная партия.

## Фактическая инфраструктура

В действующем `libre-app-1` через SSH прочитаны только три несекретных флага и hostname endpoint: `LIBRE_OBJECT_STORAGE_ENABLED=true`, `MODE=external`, `EXTERNAL_READY=true`, endpoint `s3.ru-3.storage.selcloud.ru`. Ключи, имена бакетов/объектов, пользовательские файлы и полный environment не выводились. Это подтверждает подключённое файловое хранилище Selectel S3; доступность каждого объекта и скорость обращения отдельно не проверялись.

В `libre/src/lib/object-storage.server.ts` и вызывающих API уже разделены авторизация файлов и чтение неизменяемых байтов с проверкой хеша/кэшем. С ним связаны media, illustrations и text-sources/text-editions. В compose предусмотрен собственный дисковый кэш файлов. В `diary/PUBLIC_DEPLOYMENT.md:90` описаны зашифрованные restic-копии БД/файлов в S3; содержимое резервных бакетов и свежесть конкретного snapshot сейчас не проверялись.

Старые документы Libreta упоминают Cloud.ru для резервирования. Их нельзя использовать как доказательство нынешнего провайдера активных файлов: runtime-флаги проверены отдельно. Для MelodiaJest можно рассматривать существующий аккаунт Selectel, выделив собственный бакет и права; приватные файлы и restic-репозитории публичным учебным хранилищем не становятся.

## Предлагаемый путь

1. Сначала выделить чистый версионированный контракт данных урока из нынешних JS-модулей. Сохранить ID, contentKind, ноты/собственные границы времени, руки/пальцы, артикуляцию, происхождение, подготовку и музыкальную версию. Генераторы, миграции, оценщики и правила остаются кодом. Не изменять immutable `lesson-review-baseline.js` и пользовательские редакции.
2. Создать небольшой индекс и пакеты по темам/разделам с загрузкой по запросу. Не заменять один большой JS одним большим JSON, загружаемым целиком при старте. Локальная раздача тех же пакетов остаётся рабочей без установки зависимостей; есть проверенный снимок для отсутствия сети/ошибок хранилища. Работа без сети сейчас не заявляется: такой кэш и fallback ещё нужно реализовать и проверить.
3. После проверки контракта можно публиковать пакеты и разрешённые нотные/аудио/MIDI-материалы в собственный бакет MelodiaJest на существующей инфраструктуре Selectel. Обновление материалов тогда отделяется от сборки оболочки. Раздача с подходящим HTTP-кэшем или CDN выбирается после замеров первого/повторного открытия и отказа origin. S3 само по себе не гарантирует уменьшение задержки.
4. Пакеты получают неизменяемые адреса по версии/хешу, маленький manifest — отдельную проверку актуальности. Сначала публикуются и проверяются все объекты, затем переключается manifest. Старые согласованные наборы сохраняются для открытых вкладок/отката; клиент не смешивает редакции. Импорт каталога, пользовательский порядок и прогресс не переписываются сетевым обновлением урока.
5. Публичное чтение разрешается только учебным материалам с подходящими правами. Для прямого browser fetch с другого origin проверяются CORS/HTTPS; ключи загрузки остаются вне клиентского кода. Прогресс, частные каталоги и резервные копии сохраняют собственные правила доступа и не смешиваются с публичной раздачей.

Первоисточники: [назначение Selectel S3](https://docs.selectel.ru/s3/about/about-s3/), [S3 как источник CDN](https://docs.selectel.ru/cdn/quickstart/), [CORS Selectel](https://docs.selectel.ru/s3/buckets/cors/). Проверены 6 ноября 2026. CORS регулирует чтение ответа браузером и не заменяет авторизацию приватных файлов.

## Критерии следующего этапа

Изолированная выгрузка одной небольшой темы с полным сравнением ID/музыкальных редакций и текста, сохранением пользовательских изменений, подготовок и классификации. Измерить размер индекса/пакетов, реальные запросы, задержку до выбора/открытия урока, работу при обрыве сети и откат между manifest. Прогресс другой редакции не получает зачёт автоматически. Содержательно проверить общий гитарный контракт без записи в `guitarjest`. Перенос всего курса и включение S3-загрузки по этой оценке не заявляются.

Исполняемый код и приложение не менялись; повтор полного `npm test` и музыкальных аудитов не требовался. Сделаны чтение метаданных, измерение размера/сжатия и один изолированный вызов существующего сборщика. Документы и JSON состояния проверяются после записи. Публикация первого статического выпуска на общем VPS остаётся возможной по прежней инструкции.
