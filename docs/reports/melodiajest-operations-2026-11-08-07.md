План: собственный канонический export recovery-v2 с проверкой формата/имени БД/известного рабочего состояния/receipt. Только пустое хранилище принимает всю копию после отдельного явного commit; занятость включает null, undefined и неизвестные ключи. Непрозрачный token и native CAS, add вместо put, успех по complete; запись атомарна. Новая музыкальная версия не создаётся, незавершённая правка не активируется автоматически. Future/stale pending и архив сохраняются как ограниченный JSON для дальнейшего приватного экспорта; текущая схема рабочего каталога должна быть поддерживаемой.

Формат v2 представляет отсутствующие core-слоты как null и не кодирует исходное физическое наличие этих ключей. Импорт будет применять эту семантику явно: null core означает отсутствие, pendingArchive присутствует всегда, даже с null. Уже занятые ключи назначения никогда не нормализуются и не удаляются. Принимается собственная каноническая сериализация: иное представление/дубликаты ключей отвергаются до записи. Это проверка формы и целостности данных, не криптографическое свидетельство автора файла.

Далее: реализация, регрессии, TypeScript и native IndexedDB с reopen/roundtrip/races/abort/quota; неизменность всех 28 публичных файлов; отдельная подтверждённая копия выбранного checkout. Публичное приложение и прежние localStorage writers не переключаются на этот store в данной фазе.


Важная граница существующего формата: recovery-v2 содержит каталог и прежний снимок, но не отдельный журнал MIDI-прогресса из LEARNING_STORAGE_KEY. Новая функция не объявляется его резервной копией. До подключения общего store необходимо отдельно согласовать перенос этого ключа, pending-журналы и все прежние writers. Личные настройки MIDI/звука также не входят в этот файл. Текущий код их не читает и не изменяет.
