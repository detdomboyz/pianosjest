## Изменение

`sidebarActiveHeader` находит собственный `.theme-row` через ближайшую `.theme-group`. Ограниченная коррекция использует его текущий `getBoundingClientRect`, учитывая переносы строк, и центрирует в оставшейся видимой области. Заголовок целиком выше/ниже списка не уменьшает её. Позиция зажимается существующими0/maxScroll. Слишком высокая строка не получает невозможного обещания полной видимости.

Имеющиеся два RAF, один scheduler с ticket и проверки памяти/инвалидации/отключённого follow/урока/фильтра/sidebar/row сохранены. Добавлена проверка личности заголовка до геометрии как в queued resize, так и в отложенной коррекции. Замена одного заголовка отменяет старое действие. Polling, дополнительные циклы, полная перерисовка, зависимости и CSS не добавлены. Весь `index.html` за пределами этих функций точен: оценщики, рендер, клавиатура, обработка памяти и CSS не менялись.

Прочитаны [Vercel Web Interface Guidelines, Focus States/Performance](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) и [CSS Positioned Layout3, §3.4/3.4.1](https://drafts.csswg.org/css-position-3/#sticky-pos). Vercel требует не закрывать фокусированный элемент; в160 строка была выбрана, фокус именно на ней не доказан. Это контекст, не подмена наблюдения. CSSWG объясняет привязку sticky к scrollport и возможное перекрытие; это редакторский проект14мая2026, не окончательная неизменная норма. Источники не диагностируют наше приложение и не предписывают JS/RAF/числовую коррекцию. Свои геометрические решения авторам не приписываются.
