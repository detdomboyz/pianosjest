# Музыкальный документ v1: проверяемый пилот

Статус выпуска **23.5.19**: чистый контракт и обратимая совместимая проекция для чтения. Это подготовка миграции, без нового редактора партитуры, переноса интерфейса React/Next.js и изменения формата сохранения. [Проверка этапа](reports/piano-curriculum-2026-11-06-14.md).

## Исполняемые границы

`music-document.js` / `.d.ts` описывают и проверяют документ: версия схемы, ID документа и редакции, партии, отдельные ноты, звучащие высоты и индивидуальные интервалы звучания. Известное время хранится в единицах четверти как исходные числовые `start` и `duration`, без квантования и пересчёта в фиксированные тики. `span.kind = unknown` не содержит выдуманных начала и длительности. Числа 1/3 и 2/3 сохраняются как исходные JavaScript Number; это не обещание произвольной рациональной точности.

Высоты различают целочисленный MIDI 0–127, явную частоту Hz и непитчевое событие по ключу. Частота 660 Hz не округляется в MIDI. Это возможности хранения и проверки модели, без утверждения, что текущий пианистический звук или оценка уже исполняют частоты, ударные либо удержанные голоса. Дубликаты ID, неизвестная партия, неоднозначное неизвестное время, неверная высота и неизвестная версия отклоняются.

`piano-catalog-adapter.js` / `.d.ts` содержат:

- `KEY_MAP` и `parsePattern` — реальный разборщик, выделенный из `index.html` и используемый приложением. Порядок аккордов, `{быстрые группы}`, пробелы, неизвестные символы и прежнее поведение незакрытых скобок сохраняются.
- `project(entry)` — чистое представление одной записи каталога v7. Каждая клавиша получает отдельную ноту. Руки и пальцы из совпавшего явного `fingeringSpec` связываются с ID нот отдельно от их высот; регистр не переопределяет указание руки. Недействительные назначения архивируются с предупреждением, без пальца-заглушки.
- `restore(projection)` — обратное преобразование проверенной проекции. Полная исходная JSON-запись хранится в `compatibility.entry`, включая инструкцию, редакции, автоматический план, порядок, классификацию и неизвестные расширения. Функция повторно проверяет соответствие музыкального графа источнику и отклоняет неподдерживаемые изменения графа или полей; изменения не теряются молча.
- `roundTripCatalog(snapshot)` — самостоятельная проверка всего JSON-каталога с сохранением тем и порядка. Используется инструментами разработки. Обычные сохранение, экспорт и импорт приложения остаются на прежнем пути.

## ID и прогресс

ID ноты детерминирован из инструмента, ID записи, редакции каталога, индекса действия и индекса ноты в нём. Он устойчив для той же редакции; устойчивость через музыкальное редактирование не обещается. Перед будущим редактором потребуется сохраняемая идентичность нот и явное сопоставление редакций.

В выпуске 23.5.21 исправлены генерируемые ID двух тем нового встроенного каталога: 15 ссылок теперь совпадают между чистыми запусками. Сохранённый каталог и его обратное преобразование сохраняют исходные непрозрачные ID. Если ID нового создания занят другой личной темой, выбирается свободный суффикс; существующие пользовательские ID не перенумеровываются. Сохраняемая идентичность отдельных нот через музыкальное редактирование остаётся будущим этапом.

**Редакция документа каталога не является отпечатком зачёта.** Она получает пространство `piano-catalog-v7:`. Каталог не содержит некоторые индексы ритма, которые текущий runtime восстанавливает, поэтому его сырая подпись отличается от подписи исполняемого урока. Например, у левой группы чёрных сериализованный источник даёт `567b2cf1`, текущий зачёт — `ef39f991`. Адаптер не использует новую редакцию для выдачи или переноса зачёта.

Отдельный аудит восстанавливает весь каталог в изолированной копии настоящего приложения и сравнивает все 569 прежних runtime-отпечатков. Настоящее хранилище прогресса не открывается и не переписывается. Каталожный JSON по-прежнему не является архивом прогресса.

## Достоверность старых данных

У 141 записи нет точного ритма: 16 145 нот получают неизвестное время. Пробелы и быстрые группы не превращаются в четверти или точный ритм пьесы. Исходные поля сохраняются полностью.

Старый пианистический формат задаёт одну длительность на действие. 3 258 многозвучных действий отмечены `LEGACY_SHARED_CHORD_TIME`; отдельные окончания из такого источника восстановить нельзя. Общая модель допускает разные интервалы нот, но `restore` отвергает такую новую редакцию, пока нет соответствующего адаптера и исполнительских проверок. Педаль, голоса, карта темпа, размеры, исходные MIDI-вложения и нотная орфография пока остаются в совместимом источнике, если они там есть; полноценный импорт этих сущностей не объявляется готовым.

## Производительность и проверка

На локальном каталоге: **569** записей, **39 247** нот, JSON **8 050 304** байта. Пробное синхронное преобразование перед выгрузкой добавляло около **1083 мс** к записи JSON около **42 мс** в одном локальном замере. Этот путь исключён из финальной реализации: тяжёлая проверка вызывается явно через **`npm run audit:music-document`**. Замер не является общей оценкой скорости приложения; отдельный длительный ответ браузерного инструмента при скачивании также не считается временем выполнения приложения.

Основные проверки: `npm test`, `npm run audit:music-document` и прежние аудиты. Строгая проверка типов выполнена уже установленным TypeScript **5.8.3** из соседнего портала, с `--noEmit`; его файлы и зависимости не менялись. Текущий локальный запуск не требует TypeScript или установки npm-зависимостей.

Первоисточники: [TypeScript — Modules .d.ts, Optional Global Usage и Testing your types](https://www.typescriptlang.org/docs/handbook/declaration-files/templates/module-d-ts.html); [MusicXML 4.0 — duration](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/duration/) и [chord](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/chord/). MusicXML различает длительность, запись и исполнительские attack/release, а также допускает более короткую добавочную ноту созвучия. Наши поля и решения — контракт проекта, без заявления о поддержке MusicXML.

Следующее применение — один компонент чтения в отдельном необязательном веб-пакете после малой музыкальной партии. Для него использовать этот контракт и явные ограничения, сохраняя текущие MIDI, звук, пользовательские редакции и прогресс. Вход портала и публикация остаются отдельными этапами.

## Конечная пауза в каталоге 23.5.22

В одном новом уроке `learning.ending` задаёт конец после последнего NoteOff. Адаптер сохраняет поле полностью в `compatibility.entry.learning.ending` и точном возврате v7. Сам `music.notes` по-прежнему описывает только звучащие ноты; наличие архива не означает готовую общую модель редактора пауз. Действующий тренажёр читает ending из каталога, не выводит его из последнего окончания нот и не выдаёт версию проекции за зачёт. Подробный исполнительский контракт — [PIANO_ENDING_V1](PIANO_ENDING_V1.md).
