# Импорт файла recovery-v2 в пустое хранилище

Фаза 2026-11-08-07. Контракт реализован в `piano-lesson-package-store.js` и контроллере, проверен на синтетических данных. Публичное приложение 23.5.54 и его прежние writers не подключены. Это продолжение [экспорта архива](PENDING_ARCHIVE_CONTRACT.md) и [отдельного возвращения pending](PENDING_RESTORE_CONTRACT.md).

`prepareRecoveryImport(text)` принимает точный собственный export `melodiajest-piano-package-recovery-v2`. Проверяет семь полей обрамления, имя БД, поддерживаемые рабочие состояния v7, последовательные revision и согласованную receipt. Декларируемые pins имеют прежнюю структурную проверку; файл не становится криптографическим свидетельством автора или проверенным пакетом издателя. Схемы 1–6 и будущие рабочие состояния не адаптируются.

Сериализация должна совпадать с собственным экспортом. Это отсекает дубликаты JSON-ключей, изменённые числовые/строковые представления и форматирование, которые нельзя считать теми же экспортированными байтами. Файл не редактируется. Общий предел — 320 МиБ UTF-8 JSON, известный каталог — 32 МиБ, pending и архив — до 96 МиБ каждый; прежние ограничения строк, узлов и глубины сохраняются. Материал не обрезается. Испытания не заполняли память файлом предельного размера.

Подготовка делает только readonly-проверку пустоты через `getAllKeys(undefined,1)`. Любой существующий ключ, включая неизвестный, null и undefined, даёт CONFLICT. Непрозрачный замороженный token содержит version, database, sourceRevision и bytes, без каталога. Payload хранится в WeakMap того же store; контроллер отдельно учитывает собственные разрешения. JSON-копия, другой store/controller и закрытое соединение не дают права записи.

`commitRecoveryImport(plan)` ставит действие в очередь контроллера. Одна короткая native readwrite-транзакция повторяет проверку всех ключей и использует только `add`. Нет `put`, удаления или замены имеющихся данных. Успех возвращается по complete; abort и внедрённый QuotaExceededError откатывают все добавления. Strict — durability hint, не гарантия при любой аварии питания. После успешного импорта рабочий current из файла доступен через отдельный read; контроллер сообщает recovery-imported, не обычное saved. Pending и архив никогда не возобновляются автоматически.

| Исходник recovery-v2 | Действие |
| --- | --- |
| Ненулевой core-слот | Добавить исходное значение в пустую БД |
| Null в current/previous/receipt/pending | Ключ не создавать: v2 так представляет отсутствие |
| pendingArchive, в том числе null | Сохранить присутствующий ключ и значение |
| Future/stale pending или неизвестный архив | Сохранить ограниченный JSON; отдельное восстановление может отказать |
| Уже занятое назначение | Отказать, не нормализовать и не удалять записи |

Формат v2 не кодирует исходное физическое наличие core-ключей с null/undefined. Импорт не заявляет восстановление этой отсутствующей информации. Занятые ключи назначения защищаются независимо от значения. Сразу после импорта и reopen полный повторный export совпадает с исходным текстом; ноты, ритм, пальцы, порядок, классификация и редакции каталога сохраняются.

Повтор живого token возвращает replayed только при точном совпадении всех ожидаемых ключей и значений. Конкурентная другая копия или writer дают STALE. Подтверждённый token не создаёт данные снова, если после его завершения БД была очищена. Повторная новая подготовка для непустой БД требует отдельного будущего сценария разрешения конфликта.

Существенная граница: существующий recovery-v2 **не включает отдельный журнал MIDI-прогресса из LEARNING_STORAGE_KEY**, его pending-журналы или настройки MIDI/звука. Это не полная резервная копия личных данных приложения. Перед production-подключением нужно согласовать эти компоненты и все legacy writers; VPS/S3 также не покрывают данные браузера автоматически.

Проверки: 12 новых Node-регрессий, 42 целевых вместе с прежними, TypeScript 6.0.3 strict/noEmit на уже установленном компиляторе. [Native QA](qa/melodiajest-2026-11-08-07-recovery-import.json) — 20/20: File.text, полный reopen/export, отдельный resume, занятые null/undefined, два IDB-соединения, гонка разных копий и writer, native abort после add, внедрённый quota после второго add, отказ чужим token. Это два соединения одной страницы, не две вкладки. Физический disk-full, аппаратный power-loss и настоящий файловый picker не проверялись. Синтетические БД удалены; localStorage origin не менялся. Проверены Enter, focus-visible, aria-live=polite, кнопка 44 px и отсутствие горизонтального переполнения при 390 px.

Воспроизведение без установки зависимостей:

```powershell
node --preserve-symlinks --preserve-symlinks-main --test tests/piano-recovery-file-import.test.cjs
node --preserve-symlinks --preserve-symlinks-main tools/qa-piano-recovery-file-import.cjs
```

Открыть `http://127.0.0.1:63349/` и нажать кнопку проверки. Host loopback раздаёт только allowlist модулей и синтетический fixture. После прерванного запуска стенд может удалить до 64 собственных disposable-БД с точным task-префиксом `melodiajest-piano-packages-v1-qa-import07-`; canonical БД и другие QA-префиксы исключены.
