# Подготовка личного v7-черновика после исходной копии

Эксплуатационная фаза 33 от 7 ноября 2026. На момент этой проверки сайт оставался 23.5.48. Изолированный `piano-lesson-package-controller.js` получил два явных действия: `prepareLegacyV7` и `exportLegacyPreparation`. Модуль не включён в браузерный allowlist production и не переключает каталог. Это контракт подготовки, а не завершённая миграция приложения. В фазе 35 добавлен [стандартный reader текущего v7](LEGACY_V7_ADAPTER_CONTRACT.md); описание ниже фиксирует исходную проверку фазы 33.

1. Требуется настоящее разрешение verified-loader, фиксированный legacy-ключ, инъекция проверенного raw-copy модуля и синхронный доверенный адаптер. Неверный вход отклоняется до I/O.
2. Raw-copy снимает исходную строку до первого await. Контроллер ждёт strict commit, затем проверенное чтение с ID, ключом и точной строкой. Ошибка места, ёмкости, структуры или целостности не допускает разбора. Четыре прежние копии не удаляются автоматически.
3. Существующий current v7 запрещает подготовку. Исходная строка повторно сравнивается перед адаптером и после него. Адаптер должен явно вернуть поддерживаемый catalog v7; автоматическое исправление повреждённой строки отсутствует. Отсутствие ключа передаётся как null, а не пустая строка. Реальный production-адаптер со всеми прежними полями ещё не подготовлен.
4. Store.validateCandidate захватывает ограниченную JSON-копию результата: музыкальные редакции, личные ноты/пальцы, классификация, порядок и дополнительные данные не теряются при позднем изменении объекта вызывающей стороной. Сам план содержит только метаданные, привязан к экземпляру контроллера через WeakMap и не восстанавливается из JSON.
5. Только явный export возвращает приватный JSON `melodiajest-legacy-v7-preparation-v1`: candidate, ID исходной копии и `activationPerformed:false`. Перед экспортом источник сравнивается снова. Обнаруженный STALE отзывает разрешение; возврат прежней строки его не оживляет. Исходная raw-копия остаётся отдельно доступной для явного восстановления/экспорта.
6. Контроллер сообщает `legacy-prepared`, а не `saved`. Подготовка не вызывает store.prepare/stage/commit, не пишет localStorage, не меняет UI, прогресс, MIDI или звук. Существующий pending не активируется и не разрешается этим действием. Закрытие до завершения raw commit блокирует поздний разбор; уже сохранённая исходная копия остаётся.

Сверки источника не являются общей транзакцией localStorage/IndexedDB и не исключают незамеченный цикл A→B→A. Между возвратом экспортированной строки и её будущим применением источник тоже может измениться. Поэтому здесь нет метода активации. В index.html обычный saveCatalog и импорт независимо пишут legacy-ключ; editors/delete/reorder/fingering вызывают первый путь. Прежде чем включать v7 в приложение, нужно согласовать оба пути записи и остальные writers, определить разбор stale/future pending, проверить все личные поля реальным адаптером и восстановление после закрытия вкладки. Новая блокировка, которой старые writers не пользуются, общей защитой не считается.

Проверка: 8 новых Node-сценариев плюс 10 прежних контроллера; 12 сценариев настоящего IndexedDB на собственном loopback-стенде. Native abort отменяет add; quota внедрена в native-транзакцию, фактическое исчерпание диска не проверялось. Проверены точный readback до адаптера, поздние изменения, повреждённый UTF-16 исходник, missing, заполнение без удаления, существующий v7, чужие разрешения и закрытие. Все ключи localStorage стенда сохранены, тестовые базы удалены. Чужие приложения и реальный пользовательский каталог не подключались; реальных двух вкладок для этого нового метода и браузерной независимой копии не заявляем.

Первичные источники, прочитаны 07.11.2026: [WHATWG Web Storage §12.1](https://html.spec.whatwg.org/multipage/webstorage.html#introduction-16) прямо не обещает межпроцессную блокировку; [W3C IndexedDB §2.7.1](https://w3c.github.io/IndexedDB/#transaction-lifecycle) и [commit](https://w3c.github.io/IndexedDB/#commit-transaction) отделяют завершение от запроса и требуют атомарности commit/abort. Дополнительные сверки и запрет активации — решения проекта. QA-интерфейс проверен по [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md): семантическая кнопка 44 px, Enter, aria-live, перенос JSON, 390×844 без горизонтального переполнения. Реальная видимость focus-visible после изменения viewport отдельно не подтверждена; CSS-правило сохранено. React/Next, зависимости и плагины не менялись.
