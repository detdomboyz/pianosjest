# MelodiaJest: учебные испытания, опыт и общение

Указание пользователя 8 ноября 2026: обучение становится последовательным испытанием; его прохождение и результаты хранятся в серверной БД. Обычный режим — по порядку без пропусков, свободный выбирается в настройках. Опыт зависит от проверяемого качества исполнения. Пользователь отдельно подтвердил: **один общий уровень и сумма XP Libreta + Praicer + MelodiaJest**. В 23.5.64 опубликованы собственная PostgreSQL, испытания/XP/прогресс, оценки, комментарии и новый интерфейс. Общая сумма/уровень трёх сервисов требуют следующего отдельного этапа SSO и общего журнала.

## Проверенные исходные правила

- Libreta `src/lib/profile-sidebar.ts`: уровень `floor(sqrt(xp / 120)) + 1`; начало уровня `120 * (level-1)^2`, следующая граница `120 * level^2`. Сегодня Libreta вычисляет XP из собственного чтения/оценок/черновиков/комментариев/публикаций. Общего журнала трёх приложений пока нет; нельзя выдать музыкальный локальный XP за уже объединённый.
- Libreta `src/lib/ratings.ts`: шкалы `ten`, `ten_decimal`, `hundred`, `five`, `three`, `two`, единое значение 0–100 и сохранённое точное значение выбранной шкалы. Целая десятибалльная/стобалльная при точном x,5 округляют вниз. Пятибалльная имеет опоры 10/25/50/75/95, трёхуровневая —20/50/80, лайк/дизлайк —80/20. Ноль — оценка; отсутствие оценки — null.
- Стандарт MelodiaJest по указанию пользователя — целая десятибалльная. Публичная средняя урока всегда дробная десятибалльная с числом голосов, независимо от личной шкалы. Переключение вида не переписывает саму оценку и не накапливает округление. Вес рецензий Libreta не переносится в уроки автоматически.
- Оценка **исполнения** и пользовательская оценка **урока** — отдельные данные. Комментарии/оценки урока не подменяют MIDI-зачёт и не дают ручного прохождения обязательного шага.

## Визуальный план

Музыкальная дорожка, а не таблица заданий: маршрут похож на вертикальную партитуру с отмеченными пройденными звуками и одним выразительным ближайшим испытанием. Экран игры сохраняет крупные ноты и клавиатуру; обсуждение и оценка раскрываются вне активной попытки. После подтверждения сервером — крупный результат и короткая анимация опыта/перехода уровня, без непрерывного конфетти.

Цвета: сцена `#091321`, поверхность `#111f30`, свет нот `#f4f7fb`, пульс `#78d6d1`, маршрут `#ad9bff`, награда `#f0c36a`, исправление `#fa9383`. Bahnschrift для выразительных заголовков/чисел, Segoe UI/system для чтения. Цвет не заменяет текст состояния; все действия доступны клавиатурой, движение отключается через prefers-reduced-motion.

```text
MelodiaJest   Обучение  Произведения  Сообщество   Аккаунт / общий LVL

Твой следующий звук            [продолжить испытание]
Цель, рука, небольшой блок     текущий XP → следующая граница

глава / навык     нотная дорожка: пройдено → сейчас → закрыто
                 название, краткая цель, оценка x,xx/10

результат: ноты / пульс / удержания · подтверждённый опыт
          повторить / следующий шаг · обсуждение и оценка урока
```

План проверен по brief: главный объект — музыка/исполнение; опыт и маршрут отвечают на действия, социальные элементы вторичны. Не добавлять фиктивные голоса, уровни других приложений или успешное сохранение до ответа сервера.

## Серверные границы

Канонические задания/версии и правила наград задаёт сервер. Клиент не присылает доверенные XP или флаг «пройдено»; сервер заново оценивает допустимую последовательность MIDI-событий и время, связывает попытку с пользователем, уроком и музыкальной версией. События браузера не доказывают пальцы, художественное качество и физический источник сигнала.

Повтор одного результата не начисляет опыт дважды. Улучшение даёт только разницу до лучшего результата той же учебной цели; переименование/BPM-вариант не создаёт новую цель награды. Неизвестный ритм/неподдерживаемый материал остаётся практикой без ложного зачёта. История попыток и прежних редакций сохраняется.

Для общего уровня нужен подтверждённый общий субъект аккаунта и единый серверный журнал событий с ключом дедупликации источника. Не объединять независимые аккаунты по имени/email. До подтверждённой SSO-связи нельзя показывать выдуманный суммарный уровень; музыкальный вклад сохраняется отдельно для последующего подтверждаемого переноса.

У пользователя должен быть **один LVL**, поэтому неподключённому аккаунту показывается сохранённый музыкальный XP, без второго самостоятельного счётчика LVL. Формула Libreta и музыкальная оценка вклада подготовлены для общего журнала; красивый результат и анимация XP не выдаются за уже изменённый уровень в соседних приложениях. Объединение через SSO — следующий отдельный этап, как и указал пользователь.

Для многопользовательского журнала попыток, XP, оценок и обсуждений целевой backend — **собственный PostgreSQL** с транзакциями и индексами; SQLite остаётся совместимым локальным/переходным вариантом. Не использовать базу или роли Libreta/Praicer. Переход только после актуальной копии, изолированного импорта/сверки всех UUID/хешей/редакций, проверки доступа и обратимого переключения на совместимый backend; не копировать чужой PostgreSQL.

Источники выбора БД: [PostgreSQL MVCC](https://www.postgresql.org/docs/current/mvcc-intro.html), [SQLite: выбор embedded/client-server](https://sqlite.org/whentouse.html). Рекомендация основана на одновременных записях многих пользователей, а не на предположении, что SQLite вообще не поддерживает многопользовательские сайты.

Общие и поурочные комментарии читаются публично; запись/собственная редактура — только после входа. Личная оценка одна на пользователя и редакцию, ноль сохраняется. Чужие приватные данные, сервисные секреты и MIDI-журналы в публичную выдачу не попадают.
