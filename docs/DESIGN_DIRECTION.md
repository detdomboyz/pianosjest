# Направление интерфейса MelodiaJest

Обновлено 5 ноября 2026 по запросу пользователя. Это музыкальное рабочее место для человека у настоящего пианино. Главный объект — ноты, текущая цель и клавиатура. Разбор помогает начать движение и остаётся доступным во время практики, но не вытесняет инструмент.

## Визуальная основа

Палитра: фон `#091321`, поверхность `#111f30`, разделитель `#30455b`, основной текст `#f4f7fb`, вторичный текст `#b6c7d8`, действие `#78d6d1`. Существующие смысловые цвета пальцев, ошибок и нот сохраняются. Матовые поверхности и тонкие разделители напоминают пюпитр; новые декоративные градиенты не нужны.

Шрифт: локальный `Segoe UI Variable`, затем `Segoe UI` и системный sans-serif. Для короткого названия — локальный `Bahnschrift` с тем же запасным семейством. Внешних запросов к шрифтам нет. Основной текст 14–16 px, межстрочный интервал 1.6, текст разбора до 76 символов по ширине. Заголовки короче и заметнее основного текста, без дополнительного декоративного ярлыка.

```
MelodiaJest                           MIDI / звук
Обучение | Произведения
┌ маршрут ─────────┬ урок / режим / результат ───────────┐
│ этапы и уроки    │ Разбор: Кратко ▾                   │
│                 │ до 5 строк → развернуть весь блок  │
│                 │ управление воспроизведением        │
│                 │ нотная строка / текущая цель       │
│                 │ клавиатура и пальцы                │
└─────────────────┴─────────────────────────────────────┘
```

На узком экране колонки переходят в последовательные блоки, длинный текст переносится. Клавиатура сохраняет собственную прокрутку. Описание не создаёт горизонтальную прокрутку страницы.

## Разбор урока

- По умолчанию краткий: цель и начало подготовки, максимум пять строк; вся область превью — настоящая кнопка. Нажатие, Enter и пробел открывают полный текст.
- Режимы «Кратко», «Развёрнуто», «Скрыто» сохраняются в прежнем хранилище настроек интерфейса. Выбор остаётся снаружи блока, поэтому скрытый разбор легко вернуть.
- Полный текст включает подготовку, старые исполнительские рекомендации, происхождение и источники. Ссылки внутри открытого текста остаются обычными ссылками.
- В раскрытом разборе подготовительные задания показываются своими названиями и открываются кнопкой. Это переход к конкретному упражнению в «Обучении»; выбор произведения не становится учебной предпосылкой. После перехода фокус получает название урока, звучащие ноты и текущая попытка останавливаются штатным выбором урока. В кратком виде дополнительные кнопки не занимают место.
- В попытке из памяти учебные подсказки отсутствуют в DOM независимо от настройки. После попытки выбор пользователя восстанавливается.
- Режим памяти также заменяет название задания и список каталога нейтральным блоком: название с нотами само может подсказывать ответ. Возврат к практике виден явно, завершает текущую попытку и сохраняет историю результатов.
- У повторного одиночного звука текущая цель коротко напоминает о новом нажатии. При точном ритме указание «быстро» из старых фигурных групп не показывается. В памяти отсутствуют также эта подсказка и подписи октав скрытой клавиатуры; обычный вид возвращается в практике.
- Учебное объяснение сохраняет правильную запись ноты в гармонии: для C minor это E♭. Пока клавиатура подписывает соответствующую клавишу D#, карточка явно объясняет совпадение. Будущий типовой документ должен хранить нотную орфографию отдельно от звучащей MIDI-высоты.
- Большой текст создаётся только при раскрытии. Это первое выделение самостоятельного представления из монолитного HTML перед постепенным переносом в React; музыкальный расчёт не дублируется.
- Повторение той же цели подписывается в кратком виде. В полном разборе есть одно именованное действие к основному уроку; одинаковая кнопка не дублируется среди подготовки. Связь не объединяет личные результаты двух записей и не увеличивает число самостоятельных целей.
- При четвертной единице пульса текущая нота длительностью 1,5 доли получает короткую подсказку «полторы доли, как три равные восьмые». В размерах с другой единицей это название не применяется. В памяти подсказка отсутствует, настройка вида описания её не возвращает.
- Если после начала попытки памяти использован образец или открыт редактор, причина отсутствия зачёта показывается сразу рядом с режимом и объявляется через вежливую live-область. Новая попытка очищает статус; успешные результаты прежних попыток не удаляются. До первой ноты образец допустим и останавливается первым игровым нажатием.

## Критика и проверка

Слишком много панелей и текста над нотами замедляет начало игры. Первый шаг уменьшает именно эту нагрузку, а не добавляет большую обложку. Режим попытки и её результат остаются видимыми. Нельзя прятать предупреждение о невозможной аппликатуре или действующий статус MIDI вместе с описанием.

Кнопки имеют видимый фокус и достаточную область нажатия. Нет обязательной анимации, внешних шрифтов или перехвата прокрутки. Проверка: клавиатура, мышь, узкий экран, длинный текст, перезагрузка, скрытый режим, попытка из памяти, прежние данные и прогресс.

Применены проектные навыки `frontend-design`, `web-design-guidelines`, `react-best-practices`; выбор через `find-skills`. Источники и версии установки описываются в `PROJECT_SKILLS.md`. Проверка интерфейса не является проверкой игры на физическом инструменте.
### Смена позиции в текущей цели

Короткое предупреждение о переносе руки показываем рядом с действием, к которому оно относится. Оно берётся из явной редакторской записи `learning.positionCues`, а не выводится автоматически из расстояния между нотами. В Twinkle это переход к D4–A4 и возврат к C4–G4; всю методику не повторяем в правой колонке. Текст экранируется, не появляется на соседних действиях и скрыт при отключённых пальцах. В попытке памяти учебных подсказок нет в DOM. Вид длинного разбора и музыкальная версия от этой подсказки не зависят.
### Счёт длинного окончания

Целая нота в 4/4 получает короткий текст счёта рядом с текущей целью: один звук на четыре четвертные доли, отпускание у следующего «раз». Подсказка не должна подменять удержание четырьмя атаками. У других размеров и длительностей она отсутствует: длительность сама по себе не определяет правильную группировку счёта. Полный разбор остаётся свёрнутым по умолчанию, в попытке памяти учебный счёт отсутствует в DOM. Добавление пояснения не создаёт новую музыкальную версию или новый урок.
### Передача между руками

В последовательном упражнении смену руки поясняем рядом с текущим действием: прежний звук заканчивается у вступления новой руки. Пояснение требует явного редакторского `handoffCueProfile: sequential-release` и одиночных назначений рук у двух соседних действий. Смена регистра сама по себе не доказывает отпускание: в многоголосной музыке прежний звук может продолжаться. Поэтому подсказка не включается автоматически для всех пьес, аккордов или удержанных голосов. При скрытых пальцах и в памяти она отсутствует. Связь повторения с основной целью показываем существующей именованной кнопкой, сохраняя оба ID и историю.
### Практика без взгляда и проверка памяти

Когда пользователь включает практику без взгляда на руки, рядом с выбором режима показываем короткий статус: экранные подсказки остаются. Для подготовленного урока доступна именованная кнопка «Проверить память по MIDI». Она начинает отдельную попытку, освобождает активные ноты и переносит фокус на заголовок; устройство не подключается автоматически. У неподготовленного материала переход недоступен. Кнопка перехода оформлена в существующих токенах тренажёра, имеет высоту не менее 44 px и помещается на узком экране; итог проверен в браузере. Переключатели без взгляда имеют `aria-pressed` и сохраняют фокус после обновления. В памяти статус практики, кнопка перехода и учебные материалы отсутствуют в DOM, независимо от настройки вида описания.


Для подготовленного контракта общего окончания v2 рядом с текущим аккордом показываем короткое объяснение: удерживать все звуки до указанного конца и отпускать вместе. Из любого произвольного аккорда или будущего удержанного голоса этот приём не выводим. При проблеме аппликатуры приоритет имеет предупреждение; режим памяти полностью убирает учебную подсказку.


Составной контроль получает явную подпись «Контроль знакомых навыков» в кратком и полном разборе. Он ведёт к подготовке каждого общего компонента и не обещает новый навык из-за объединения заданий. При памяти весь учебный блок отсутствует в DOM. Роль контроля хранится отдельно от нот, версий исполнения и пользовательского порядка; счёт плана, каталога и независимых целей остаётся раздельным.


Количество действий согласуется по-русски и форматируется через Intl: 1 действие, 2 действия, 5 действий, 23 действия. Один чистый форматтер используется каталогом и диапазоном практики. Длинный учебный текст остаётся в доступном раскрытии; добавление левых половинных/целых не меняет длину стандартного превью.

### Длительность без приблизительного названия ноты

Значение 0,65 доли показываем числом; восьмая соответствует 0,5 четверти, а не близкому диапазону. Полное название стандартной ноты доступно в текущей цели и подсказке, в тесной карточке достаточно соответствующего знака. Числа локализуем; если представление округлено, ставим «≈». Длительность звука и следующая атака остаются отдельными данными. Подпись переносится, не меняя музыку, оценку или скорость звука. В памяти весь учебный холст и текущая длительность скрыты.

### Темп и время текущей цели

При изменении BPM сразу обновляем миллисекунды нот и пауз в холсте и текущей цели, сохраняя фокус ползунка. Доли и исходные данные не переписываем. Если MIDI-челлендж уже начат, его темп сохранён: явно сообщаем, какой пульс держать и как начать новую попытку с другим BPM. В памяти изменение темпа не возвращает ответы в DOM. Минимальная длительность звукового предпрослушивания относится к отдельному механизму и этим представлением не меняется.

### Бемоль и подпись текущей клавиши

Если урок намеренно использует бемольные названия, показываем короткую связь с подписью текущей физической клавиши, например «B♭3 и A#3 — одна клавиша в этом упражнении». Подсказка требует явного профиля и одной допустимой MIDI-высоты. Исходные ноты, регистр и орфографию не переписываем; в памяти подсказки нет независимо от вида разбора. Развёрнутые источники и границы остаются в учебном материале.

### Подсказка отдельного переноса

Для движения между опорами текущая цель называет старую и новую ноту, руку, палец и время подготовки. Сначала сохраняется заданный конец звука, затем отпускается старая клавиша. Если вся фраза играется внутри уже подготовленной позиции, подсказка действует до начала и не требует лишнего переноса между каждой нотой. Используем явные positionCues, а не догадку по расстоянию MIDI. В памяти подсказки отсутствуют; при скрытии пальцев действует прежняя общая настройка.

## Ожидание конца и сетка настроек, 23.5.22

До конца конечной паузы текущая цель показывает ожидание тишины, а не «Готово». В памяти это заменено нейтральным статусом без подсказки момента отпускания; выбор вида разбора не возвращает скрытые материалы. Обратная связь имеет `role=status`, `aria-live=polite`. Два блока настроек клавиатуры получили одну колонку: пояснение над переносимой строкой контролов. На проверенном обычном экране ширина пояснения выросла с 0 до 834,72 px, высота первого блока уменьшилась с 617,98 до 160,53 px; это измерение геометрии, не быстродействия. При viewport 390 px ширина страницы и её содержимого — 376 px.

## Подготовка и окончание терции, 23.5.23

У четырёх компактных терций подготовительные действия ведут к собственной руке; отображаемый порядок каталога сохраняется. Действующая подсказка «Созвучие целиком» включается через их уточнённый контракт. Проверены её отсутствие в памяти, полное удаление разбора из DOM, доступное сохранённое «Скрыто» и компактное превью 112 px при высоте строки 22,4 px — пять строк. Декоративных изменений и новых CSS/JS-представлений не потребовалось.

## Будущая первая проба, партия 19

Различать открытый разбор, новую слуховую пробу, новую запись на стане и память знакомой музыки. Для слуха ответ не появляется в подписях, DOM подсказок или доступном имени кнопки. Для чтения стан остаётся видимым, а текстовая альтернатива имеет отдельный статус практики. Явные доступные действия слушать, ответить и раскрыть, клавиатурный фокус и polite-статус входят в будущие требования; их реализация и браузерная проверка ещё впереди. Текущие компактные пять строк, сохранённый вид и память не менялись.

## Нотный лист, партия 20

Отдельный просмотр сохраняет фон #091321, текст #f4f7fb, вторичный #b6c7d8, разделитель #30455b и действие #78d6d1; светлая поверхность #f4f7fb нужна для контрастного нотного стана. Segoe UI/Bahnschrift соответствуют основному сервису, локальный Bravura даёт настоящие музыкальные знаки. Пять линеек и крупная короткая фраза главные, данные раскрываются нативным summary с видимым фокусом. Без вступительной анимации, декоративной статистики и новых карточных сеток. В браузере подтверждены правильные позиции шести высот, читаемое ограничение и отсутствие горизонтального переполнения на 390 px. Это открытый образец, не новая попытка памяти/слуха.

### Партия 23: понятное отсутствие новой пробы

Весь текущий банк уже опубликован: интерфейс показывает 0 и объясняет отключение первой кнопки. Отдельное действие меняет фразу в практике, не имитируя проверенный прогресс. Нативные Enter/пробел, видимый способ вернуть скрытый разбор и нотный лист сохранены. При 390 px clientWidth/scrollWidth 376/376; дизайн не объявляется ускорением без измерений.

### Партия 25: перенос и ошибка сохранения

Журнал подготовок свёрнут по умолчанию и не вытесняет ноты. Ошибка записи видима, раскрывает повтор/экспорт, несохранённые данные обозначены отдельно от прежнего зачёта. Нативные кнопки имеют минимум 44 px, фокус видим; устаревший JSON убирается после изменения журнала. В памяти экспорт отсутствует в DOM. Проверка обычной сборки при 390 px дала clientWidth/scrollWidth 376/376; поле JSON шириной 318,4 px. Сохранены палитра/локальные шрифты и пятистрочный разбор.

### Партия 27: явно выбранная короткая подготовка

Область полного/пятинотного упражнения находится перед режимом практики. После начала смена заблокирована до сброса; память скрывает сам выбор с ответами. Использованы существующая палитра/типографика и нативный select высотой 44px, focus-visible. Разбор ленивый и подчиняется общей сохраняемой настройке. На 390px client/scroll 376/376, select 318,4px, превью около четырёх строк. Журнал остаётся свёрнутым служебным блоком и явно показывает ошибку/повтор; новый JSON охватывает обе области.
### Партия 28: подтверждённое сохранение результата

При неудачной записи прежнего прогресса счётчик показывает подтверждённую историю, рядом доступен статус о несохранённом результате. Общая панель восстановления включает оба MIDI-журнала и операции старого счётчика; повтор и JSON остаются рядом с объяснением. Клавиатурное раскрытие сохраняется во время асинхронных обновлений. В памяти JSON и учебные материалы отсутствуют. На 390 px client/scroll 376/376, JSON шириной 318,4 px, кнопка 44 px. Палитра, ноты, компактный ленивый разбор и сохраняемая настройка не менялись.

### Партия 29: проверка копии перед переносом
