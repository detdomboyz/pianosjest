# Кандидат личного снимка: семь точных значений и память writers

8 ноября 2026, фаза 15. `piano-browser-checkpoint-candidate.js` и `.d.ts` реализуют изолированную подготовку данных. Модуль не подключён к сайту и не имеет операций записи, применения или восстановления приложения. Состояние результата всегда `prepared-incomplete`, `completeCopy: false`, `consistency: uncoordinated`.

`create({subtle, now}).prepareFrom(storage, components)` читает только семь ключей из карты writers, по одному разу. Перечисления всего origin нет. Успешно прочитанный `null` означает отсутствие; пустая строка и строка `null` сохраняются отдельно. Исключение чтения даёт `unavailable / READ_FAILED`, неожиданный тип — `READ_INVALID`. Остальные доступные значения сохраняются. Они не разбираются и не нормализуются через JSON: неизвестные поля, повреждённая строка, прежние редакции, NUL и одиночные UTF-16 surrogates остаются точными.

Значения памяти передаются владельцами явно, как непрозрачная строка или null и номер наблюдённого поколения. Внешний код должен подготовить их из реальных API; в этой фазе адаптеры владельцев не реализованы.

| Компонент | Что ещё предстоит согласовать с владельцем |
| --- | --- |
| `catalog-state` | Текущая модель, save record, raw/previousRaw, очередь и readback |
| `ui-workspace` | Текущее состояние выбора и настроек, включая неподтверждённую запись |
| `legacy-progress` | `exportRecovery()`: pending, baseRaw, draftRaw, generation |
| `whole-capture` | Подтверждённая история, pending/recent/jobs и scope |
| `fragment-capture` | Те же данные для отдельного фрагмента |
| `transfer` | Pending/prepared operation и исходная строка |
| `editor-draft` | Незавершённые MIDI/audio/rhythm/fingering редакции |
| `active-attempt` | Незавершённая попытка и отдельное решение о её переносе |

Отсутствующий компонент получает `NOT_CAPTURED`; неподдерживаемый передаётся явно как `UNSUPPORTED`. В обоих случаях данные не заменяются пустым журналом. Даже восемь наблюдённых компонентов не означают, что их содержимое проверено: причины `WRITER_BARRIER_NOT_IMPLEMENTED` и `MEMORY_CONTRACTS_NOT_VALIDATED` присутствуют всегда. Аппаратные MIDI-полномочия, AudioContext и Windows bridge не объявляются восстановимыми данными.

Все строки и поколения фиксируются синхронно до первого ожидания digest. Это сохраняет именно наблюдение, но не превращает последовательное чтение разных ключей/вкладок в общую транзакцию. Изменившийся во время digest pending остаётся у владельца. Новый Web Lock или совпавший хеш не доказывают отсутствие промежуточной записи и ABA.

Для каждого точного raw используется уже проверенный `piano-legacy-catalog-copy`: presence byte плюс little-endian UTF-16 code units и SHA256. Нормализации через UTF-8 нет. Отдельный digest манифеста связывает ключи, компоненты, их поколения, статусы и хеши. Дата наблюдения не создаёт новый контентный ID. Это выбранный протокол проекта, а не требование стандартов.

Возвращаемый token содержит только метаданные. `readCandidate(token)` — явное приватное чтение неизменяемых строк из памяти этого builder. JSON-копии, посторонние токены и сам DTO не являются допустимым token. `close()` освобождает внутреннюю связь. В модуле нет IndexedDB commit, локального файла, сетевого запроса, скачивания, импорта или функции применения к текущему прогрессу. Структурное копирование DTO в тесте не считается нативным восстановлением приложения.

Пределы проекта: 16 Mi code units на значение и 32 Mi на сумму наблюдений. Это ограничения подготовки, а не измеренный остаток квоты браузера. Слишком большой кандидат отклоняется до digest; исходные значения и ранее подготовленный token остаются доступны. Точная строка может остаться повреждённым JSON и непригодной для активации: сохранение и проверка её смысла — отдельные действия.

Проверки включают полный каталог 578 записей, реальный reducer-журнал 166 MIDI-уроков, полный несохранённый каталожный контекст, ошибки чтения/квоты и два настоящих pending-operation legacy store. Проверка типов использует существующий TypeScript 6.0.3 из VS Code, strict/noEmit, без установки зависимостей. Полная регрессия и восстановление исходников учитываются в отчёте фазы 15. Нативная проба IndexedDB фазы 12 остаётся историческим измерением и не выдаётся за commit этого кандидата.

Первичные основания перечитаны 08.11.2026: [WHATWG Web Storage §12.1/12.2.1](https://html.spec.whatwg.org/multipage/webstorage.html), [W3C Web Locks, request и scope](https://w3c.github.io/web-locks/), [ECMAScript QuoteJSONString §25.5.4.3](https://tc39.es/ecma262/multipage/structured-data.html#sec-quotejsonstring). Они подтверждают строковое чтение/null, границы координации участников и представление code units. Формат, ключи, восемь компонентов и лимиты являются решениями проекта.

Следующий отдельный этап: подтверждённая запись/чтение кандидата в собственном IndexedDB без потери прежнего, затем реальные экспортёры памяти и согласованный барьер всех writers/вкладок. До этого полный browser backup и production package-store не включаются.

Продолжение фазы17: отдельный [candidate-store](BROWSER_CHECKPOINT_STORE.md) реализует проверяемую запись и чтение DTO в собственной IndexedDB. Сам builder остаётся подготовкой без записи; полная координация owners/writers и применение к приложению не реализованы.
