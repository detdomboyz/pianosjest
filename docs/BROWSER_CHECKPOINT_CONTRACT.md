# Полный личный снимок: измерение и границы контракта

Обновление фазы 15: публичная версия уже 23.5.58. Реализована изолированная [подготовка кандидата семи raw-значений и восьми компонентов памяти](BROWSER_CHECKPOINT_CANDIDATE.md), с неизменным `completeCopy: false`. Записи кандидата в IndexedDB и общего барьера пока нет. Числа и нативные измерения 23.5.57 ниже остаются историческими и не подтверждают сохранение нового кандидата.

8 ноября 2026, эксплуатационная фаза 12. **Измерительный инструмент реализован; следующий контракт описан, но не подключён к приложению.** Публичный выпуск остаётся 23.5.57. Это не новый формат recovery, не облачная синхронизация и не подтверждение атомарности всех writers.

## Что измерено

`node --preserve-symlinks --preserve-symlinks-main tools/measure-browser-checkpoint.cjs` получает полный v7 через исполняемый `catalogSnapshot()` приложения в изолированном VM. Реальный `trainer-content.json`, browser storage и частные выгрузки не читаются. Для повторяемости только время `savedAt` заменяется фиксированным тестовым значением. Каталог сохраняет все 578 записей, 98 тем, порядок, ноты, ритм, пальцы, полные учебные тексты и прежние редакции.

Данные 23.5.57: 4 923 470 UTF-16 code units, 5 779 638 UTF-8 байт. Умножение длины на два даёт 9 846 940 байт представления code units; это не измеренный расход квоты или памяти браузера. gzip level 6 дал 333 831 байт, Brotli quality 5 — 205 247 байт, с точным восстановлением UTF-8. Сжатие в приложение не включено. Эти числа не доказывают ускорение S3/CDN, запись localStorage в сжатом виде или выигрыш времени на устройстве ученика.

В синтетический сценарий входят семь известных активных ключей из [карты writers](BROWSER_PERSISTENCE_WRITERS.md). Для 166 доступных MIDI-уроков создано 664 операции настоящим reducer `PianoProgressStore.apply`, затем проверено `inspect`. Журналы whole/fragment и transfer archive пустые и валидные. Это нижний сценарий, не прогноз объёма реальной многолетней истории. JSON-оболочка с точными строками семи значений занимает 5 498 813 code units / 6 354 981 UTF-8 байт. Экранирование вложенной строки также имеет цену.

Нативная изолированная проба на отдельном loopback origin подтвердила: каталог и семь отдельных значений записываются и читаются точно. Одна JSON-оболочка не записывается даже после удаления своих семи тестовых значений: `QuotaExceededError`, прежнее значение сохранено. В IndexedDB один диагностический record с семью строками записался, read-only транзакция прочитала его точно; дополнительно различены null/пустая строка и сохранён одиночный UTF-16 surrogate. Проверены `transaction.complete` и readback, а не переживание отключения питания. Свой тестовый database и известные ключи удалены. Максимум квоты не искался, filling loop не запускался, значение `navigator.storage.estimate()` не выдано за остаток квоты localStorage.

Следствие для проекта: вторую полную сырьевую копию нельзя проектировать как ещё одну запись localStorage на основании размера маленьких fixtures. Следующий кандидат должен проверяться в IndexedDB с полными строками и настоящими journal/pending. Удалять старые учебные редакции ради уменьшения размера нельзя. Суммы отдельных JSON-значений полей — диагностические показатели, они не являются разбиением полной строки. Самое крупное поле здесь — rhythm, около 3,05 МБ UTF-8; размер нельзя объяснять только учебным текстом.

## Предлагаемый состав данных

Для каждого из семи известных persisted keys сохраняются точный ключ и исходная DOMString либо `raw: null`, если ключ отсутствует. Строки `"null"`, `""` и отсутствие различаются. Не выполнять parse/stringify исходных значений ради нормализации копии. Неизвестные поля внутри строк, прежние музыкальные версии и частные расширения должны сохраниться. Для точной проверки уже существует подход raw-copy: presence byte и little-endian UTF-16 code units; обычный UTF-8 заменяет одиночный surrogate. Предпочесть существующий проверенный код этому повторному изобретению.

Снимок persisted values недостаточен. Отдельно нужны текущая модель каталога и точный `catalogSaveRecord.raw`, previousRaw, статус readback/локального файла, generation и незавершённая очередь. Для legacy-прогресса — `exportRecovery()` с pending/baseRaw/draftRaw/generation; для двух capture — подтверждённые histories, pending/recent/jobs и контекст scope; для transfer — pending/prepared operation и исходная строка. Их наличие и актуальность проверяются до объявления complete. Отсутствующий или неподдерживаемый компонент даёт **incomplete**, а не пустые данные и не успешный полный backup.

Редакторский черновик MIDI/audio/rhythm/fingering и незавершённая попытка требуют отдельного решения: либо предусмотренный экспортируемый контракт с происхождением, либо явное incomplete. Не выдавать сохранённый каталог за сохранённый черновик. Аппаратные MIDI-разрешения, выбранный input handle, AudioContext и нативный Windows bridge не сериализуются как восстановимые полномочия. Будущая активация package-store потребует включения его current/previous/receipt/pending/archive в тот же контракт; сейчас он изолирован от публичного приложения.

Этот allowlist не является резервной копией произвольных данных всего origin. Неизвестные ключи и schema требуют разбора; их нельзя автоматически очищать. Состав и версии проверяются отдельно от успешного чтения JSON. Открытие файла восстановления — подготовка и сравнение, а не молчаливая замена действующей истории.

## Координация writers — следующий отдельный этап

У persisted keys нет общей транзакции localStorage. Существующие progress writers используют три реальные блокировки в порядке legacy → whole → fragment. Каталог, UI/workspace и другие вкладки в этом протоколе полностью не участвуют. Новое имя Web Lock само по себе не защитит их. Двойное чтение и равенство хешей тоже не доказывают отсутствие промежуточной записи/ABA.

До production-подключения надо провести все участвующие writers через проверяемый протокол. Копия фиксирует поколения/квитанции каждого компонента и принимает complete только при согласованном чтении под действительно участвующими блокировками. Захват не должен терять поступившие MIDI-события или сбрасывать текущую попытку. Не удерживать общий барьер на время сетевого PUT; неподтверждённая локальная запись должна оставаться отдельным видимым состоянием. Поведение другой вкладки, отказ lock, quota, отмена, source change и pending во время capture проверяются до интеграции.

Новая запись назначения в IndexedDB может иметь собственную атомарную транзакцию и строгую durability, но это не делает атомарным чтение семи исходных ключей и памяти страницы. Сначала сохранить и прочитать точный кандидат, затем сравнить текущие поколения. При неизвестном состоянии сохранять прежний снимок и pending. Восстановление также требует копии назначения и повторной проверки источника; откат не должен затирать уже появившуюся чужую запись. Конкретные API, версия формата и ограничения размера пока не реализованы.

Текущий recovery-v2 по-прежнему исключает `music-learning-piano-v1` и его pending. Не объявлять его полной личной копией. VPS/S3 также не покрывают частные browser данные. Сайт, локальный сервер, MIDI/звук и все действующие ключи хранения в фазе 12 не меняются.

## Первичные основания

- [WHATWG HTML, Web Storage 12.1/12.2.1](https://html.spec.whatwg.org/multipage/webstorage.html): строки, null при отсутствии, отказ setItem до изменения значения и отсутствие гарантированного межконтекстного locking. Проверено 08.11.2026.
- [WHATWG Storage, endpoints и usage/quota](https://storage.spec.whatwg.org/): архитектура хранилищ и оценок; предположение о точном остатке localStorage из общей оценки не используется. Проверено 08.11.2026.
- [W3C Web Locks, request](https://w3c.github.io/web-locks/#api-lock-manager-request): координация участников одного origin; проект обязан подключить собственных writers. Проверено 08.11.2026; это Editor’s Draft.
- [Node zlib](https://nodejs.org/api/zlib.html), [perf_hooks](https://nodejs.org/api/perf_hooks.html): API сжатия и монотонного измерения. Пять повторов, gzip6/Brotli5 и синтетическая история — выбор проекта. Синхронные компрессоры используются только в диагностическом Node CLI, не в потоке интерфейса.

Состояния: размер и нативное ограничение **измерены**; диагностические инструменты **реализованы локально**; полный согласованный снимок и восстановление **запланированы**. Этот этап не добавляет уроков и не присваивает им новых музыкальных статусов.
