# Предложение обновления с личным каталогом, v1

7 ноября 2026. `piano-lesson-package-plan-core.js` содержит один алгоритм трёхстороннего объединения. Прежний синхронный `piano-lesson-package-update.js` проверяет package-байты через Parts и использует этот core с Node SHA256; отдельный `piano-lesson-package-planner.js` использует его с асинхронным WebCrypto. Прежние prepare/materialize и числовой порядок выпусков Node сохранены. Новых зависимостей, polyfill и изменений общего гитарного модуля нет.

## От проверенной загрузки к предложению

`Planner.create({subtle}).prepare({active, previous, incoming, catalog})` принимает previous/incoming только как оригинальные результаты Loader.load в памяти того же модуля. Loader.requireVerified проверяет WeakSet, не вызывает accessors и не принимает JSON-копию, spread или Object.freeze поддельного объекта. Тип Loaded имеет nominal brand. Это контроль происхождения внутри доверенного кода страницы, не защита от произвольного исполняемого кода того же origin; закреплённые исходные pin должны поступать из доверенного контроллера.

Loader по-прежнему проверяет все байты, размеры, SHA256, source и codec до выдачи результата. Planner не загружает сеть, CacheStorage, IndexedDB или localStorage. Подготовка предложения не сохраняет каталог и не начинает MIDI/звук. Поддельные/старые источники, иной pin того же выпуска и изменение состава пакетных ID отклоняются. Добавление/удаление встроенных ID требует отдельного контракта; пользовательские дополнительные записи сохраняются.

Core сравнивает прежний пакет, входящий пакет и личный каталог. Нетронутая встроенная запись обновляется; уже совпавшая с входящей редакция остаётся. Личные ноты, ритм, пальцы, описание, классификация, история редакции и удаление встроенного материала дают явный конфликт: всё предложение blocked, частичный кандидат не выдаётся. Личный порядок массивов, числовые order, расположение lesson.themeId и дополнительные произведения сохраняются. Прогресс исключён из каталога и автоматически не объединяется.

## Ожидание SHA256 и поздняя правка

Все входы копируются и проверяются до первого await. План содержит SHA256 канонических version/themes/lessons; savedAt в этот отпечаток не входит. При materialize проверяется точное каноническое содержимое захваченного каталога, без дополнительного асинхронного digest. Изменение нот, текста, позиции или порядка после подготовки даёт STALE; смена даты экспорта разрешена. Ожидающий digest не может подхватить позднюю мутацию исходного объекта.

Замороженное предложение непрозрачно: WeakMap связан с экземпляром planner. JSON-копия, план другого экземпляра и неразрешённый конфликт не материализуются. Возвращаемый кандидат копируется заново; его изменение не портит повторное materialize. Ограничения core сохранены: каталог 32 МиБ, строка 1 МиБ, глубина 80, миллион узлов, не более 10000 элементов/полей в одном контейнере. Циклы, getters, не-JSON объекты, дубли и root progress отвергаются.

## Атомарная запись — отдельное действие

Контроллер читает свежий `Store.read()`, готовит предложение по этому catalog, вызывает materialize с последним catalog и только затем `Store.prepare(expected, candidate)` / `Store.commit(change)`. Внутри существующего readwrite scope ещё раз сравнивается полный expected: current, previous и receipt записываются вместе, результат приходит после complete. Поздняя запись другого соединения или другой настоящей вкладки отклоняет устаревший commit и сохраняет победившую личную редакцию.

Нативная проверка на 127.0.0.1:63345 использует только синтетические 44→45 пакеты и одноразовые QA-БД. 11 сценариев проверяют действительные Fetch/WebCrypto/IndexedDB, совпадение с Node-предложением, личные редакции, ожидание digest, устаревшее предложение, источник, сеть/повреждение и две разные вкладки. Вторая вкладка отвечает через ограниченный BroadcastChannel и пишет только в `melodiajest-piano-packages-v1-qa-25-<run>-peer`; ID вкладок и клиентский ID сверены с DOM. Все QA-БД удалены после закрытия соединений, исходные synthetic progress/UI/legacy строки не изменились. Мышь/Enter, aria-live, 390×844, отсутствие горизонтального переполнения и кнопка 44 px проверены отдельно от тестов Node.

Рабочий каталог сайта остаётся на bundled-пути 23.5.44. Ни loader → planner → store, ни все прежние writers в production ещё не подключены. Следующий системный этап — единый контроллер миграции/записи с pending-копией, явным сохранением личных конфликтов, отказом до commit и проверенным восстановлением; затем измерения для решения о доставке частей. Протокол не обещает облачное сохранение браузерного прогресса, ускорение сайта или стоимость S3.

Прочитаны первичные [WebCrypto Recommendation §14.3.5](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#SubtleCrypto-method-digest), [IndexedDB §2.7.2](https://w3c.github.io/IndexedDB/#transaction-scheduling) и [complete/abort](https://w3c.github.io/IndexedDB/#transaction-lifecycle). Правила объединения, pin, лимиты, русские ошибки и сохранение редакций — решения проекта.
