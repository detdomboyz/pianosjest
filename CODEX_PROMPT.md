# Направление миграции в единый музыкальный сервис

Актуальное продуктовое решение: объединить пианино из `pianosjest` и электрогитару из `C:\Users\Alexander\Documents\web\guitarjest` в один сервис портала рядом с Libreta и Praicer. Название пока не выбрано. Общими должны стать произведения, партии, ритм, публикации и учётная запись; выбор инструмента меняет рабочую область и инструментальные подсказки. Модель описана в `docs/MULTI_INSTRUMENT_MODEL.md`, этапы — в `docs/WEB_APP_PLAN.md`, правила — в `AGENTS.md`.

Это направление будущей миграции, а не подтверждение уже выполненного объединения. Ниже сохранены требования к переносу существующей пианистической части в Next.js + React + TypeScript. Они дополняются общим музыкальным ядром, отдельным гитарным модулем и подключением к архитектуре аккаунтов портала. Текущий локальный запуск и проверенную аппликатуру нужно сохранить.

Требования:

1. Стек: Next.js App Router, React, TypeScript.
2. Сохранить текущую функциональность:
   - Virtual Piano раскладка пользователя;
   - Web MIDI input;
   - игра с клавиатуры ПК;
   - звук сайта через Web Audio API;
   - 61/76/88 клавиш;
   - настройка ширины клавиш и размера шрифта;
   - мини/вертикальные/обычные подписи;
   - жирность отдельно для нот и QWERTY;
   - цвет октав;
   - метки начала октав C1/C2/C3;
   - холст нот рядом с пианино;
   - правила `A B C`, `abcdefg`, `[abcd]`, `{abcd}`;
   - после 3 ошибок урок не блокируется.
3. Разнести код:
   - `src/lib/virtualPianoMap.ts`
   - `src/lib/lessonParser.ts`
   - `src/lib/audioEngine.ts`
   - `src/hooks/useMidi.ts`
   - `src/components/PianoKeyboard.tsx`
   - `src/components/LessonCanvas.tsx`
   - `src/components/LessonSidebar.tsx`
   - `src/components/LessonPlayer.tsx`
   - `src/content/lessons.ts`
4. Состояние хранить через React state или Zustand.
5. Не ломать управление во время таймера: таймер не должен вызывать полную перерисовку всего приложения каждые 100-200 мс.
6. Добавить возможность позже вынести уроки в JSON.
7. Сделать `npm run dev`, `npm run build`, `npm run lint`.

Главная цель: сохранить проверенную рабочую логику обоих инструментов и пользовательские данные, построив один расширяемый музыкальный сервис с полноценным переключением инструмента.
